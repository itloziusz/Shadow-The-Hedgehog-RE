# GAMEPLAY_COMMANDS — the inter-object command protocol

Objects interact by sending **command objects** (RTTI base `CharCommand`) rather than calling each other
directly: damage, death, score, springs, riding vehicles, picking up weapons, player actions, etc.
Generated by `tools/command_catalog.py` → `data/commands.csv` (89 command classes).

## 1. Mechanics (PROVEN unless marked)

- Allocation: `CharCommand_Alloc(size)` 0x801DA024 (LIKELY a command pool), then the concrete ctor.
- Base ctor `CharCommand::CharCommand(this, u16 type, …)` 0x8006E57C; the type id is the first
  constant argument; concrete payload follows at +0x14 (e.g. `ScoreCommand` v0..v4 at +0x14..+0x24).
- Command header fields used by receivers: `+0x04 u16 type` (switch key), `+0x07 u8 flags`
  (bit 0x2 = consumed/handled, set by `Player_HandleCommand`).
- Delivery: through the target object's command interface, e.g. `[[obj+0x38]]` vslot 0x10 in
  `Score_SendCommand` 0x80206740. `CharCommandManagerTask` (layer 8 "Command", created at stage init)
  runs before Gadget/Enemy/Player each frame (GAMEPLAY_UPDATE_PIPELINE.md §3).
- Receivers switch on the type: `Player_HandleCommand` 0x800A7CE4 handles 0x01–0x0B, 0x17, 0x18, 0x1C,
  0x132 (and delegates the rest).

## 2b. DamageCommand (0x007) payload (PROVEN — WEAPONS_AND_TARGETING.md)
`+0x14 f32 power`, `+0x18 Vec3 direction/source`. Every hit on the player becomes a DamageCommand with fixed power
10.0; the player's handler uses only the direction (ring loss / knockback are fixed, PLAYER_GAMEPLAY_RECOVERY.md §6).
