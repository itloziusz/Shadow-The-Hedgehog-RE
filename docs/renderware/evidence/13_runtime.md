## 5. Proposed non-patching capture protocol (not executed)

1. **Preflight and authorization.** Use only an already identified/approved debugger-capable emulator session with capture support available without modifying its configuration. If none is available under those conditions, stop and ask the operator/parent for existing captures instead. Do not launch a discovered/unknown executable, change backend/JIT/EFB-copy settings, inject PPC trap instructions, alter registers/memory, install tooling, or patch the DOL. Use emulator-managed in-memory execution breakpoints/logpoints only if they do not write guest code or persist configuration. Record the existing emulator version/backend/configuration as provenance if supplied by the operator.
2. **Identity.** Verify the DOL hash against the baseline and compare the above local instruction fingerprints in loaded memory. Resolve M/S from the real call. Record frame/VI identifier, camera pointer, PC/LR/CTR, r1/r2/r13, relevant GPRs, parameter bytes/float, valid, R/H/P, raster dimensions/format/origins and the three renderer function pointers. Without that identity, a trace from a similarly named build is not correlation to this DOL.
3. **Minimal chronology run.** Prefer logging `0x801D27FC`, `0x801D2764`, `0x8042E254`, `0x8042E838`, `0x8042E738`, `0x8042E8C0`, `0x8042E954`, `0x8042E968`, `0x8042E99C`, `0x8042E9AC` across several ordinary gameplay frames, including inactive and naturally active blur. Record all early-exit reasons and camera-begin results. Count invocations per camera/frame; do not equate task calls with displayed frames or assume single-camera behavior. Do not force parameter changes or failures.
4. **GPU command correlation.** For one eligible frame, associate each high-level marker with actual lower helper LR/raster identity and the FIFO command interval. Expected successful Save-body sequence: copy R -> draw half-size quad from selected R -> copy H -> draw full-size restore quad. Expected primary Draw sequence: bind P -> seven state requests -> one four-vertex primitive -> seven state restores. Copy source/destination arguments and resulting BP `0x49/4A/4B/4D/52` must agree with the same R/H/P objects. Repeated cached state may produce no new setter command; capture the effective GPU state at draw, not just a count of setter hits.
5. **GPU-side before/after captures.** Using the existing capture/viewer capability only, inspect EFB snapshots at exact FIFO command boundaries: (A) immediately before the primary Draw primitive, (B) after it but before unrelated post-effects/HUD; (C) before Save copy #1, (D) after Save's half-size draw, (E) after Save copy #2 plus the corresponding decoded history texture, (F) after full-size restoration. Also keep the source/history texture used at A and the next eligible primary Draw. Label each with frame/camera and command index. A CPU return-PC screenshot may show the previous presented XFB or incomplete GPU work and is not sufficient. Do not insert a guest sync call just to make screenshots line up. If command-level captures are not supported without configuration changes, report that subtest blocked.
6. **Compare predictions, not screenshots alone.** Compare A/B only in covered pixels, accounting for sampled history, alpha, UV/scale, filtering, format and write masks. Compare C/D/E/F to test downsample/capture/restore separately from blur blending. Keep pixel checksums and sampled pixel coordinates only for real captured buffers; never fabricate values. Rendering to EFB and GPU copies can live in a host texture rather than the CPU RAM view under the unchanged configuration. Record that limitation instead of enabling a different copy mode.
7. **Establish temporal age.** Compare actual event order and buffer versions across at least three consecutive eligible frame/camera intervals. If Draw precedes Save and Save captures the already blended EFB, accumulated feedback is possible. If Save precedes Draw, the sample could be from the same frame. Neither follows from the function names alone. Track whether other effects modify R/EFB between these calls. A still frame can conceal temporal blur; use naturally occurring motion, not code/config changes.
8. **Reset/first-use runs.** Observe a normal creation, natural disable/alpha-zero interval spanning a Save invocation, re-enable, and any naturally occurring scene/camera rebuild. Record the expectations below. Do not inject failed camera calls or a reset flag. If such cases do not occur, mark them untested, not passed.
9. **Deliver real observations separately.** A later operator may export to an explicitly approved new capture destination; this specialist has not created such files. Suggested record schema: `session, dol_hash, frame_or_vi, camera, event_index, PC, LR, S, enable, alpha, scale_bits, valid, raster_view, parent, copy_dst, copy_format, source_rect, clear, state_id/value, primitive, FIFO_offset, capture_id, observation`. Keep `prediction` and `observation` in separate columns. Preserve emulator/config provenance and SHA-256s of actual capture artifacts. Only rows supported by those artifacts may be labeled runtime-correlated.

### Reset / first-use predictions that matter
