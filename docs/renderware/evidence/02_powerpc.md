## 2. Verified direct call chains and state layout

The existing direct-branch index gives these call sites (`motion_blur_analysis/branches.tsv:62614,62659,62663,138315-138316`):

```text
801D20B4 -> 801D20D8                        SaveScreen child construction
801D2770 -> 800A35D8; 801D2774 -> 8042F140 -> [call 8042F158] 8042E838
801D2808 -> 800A35D8; 801D280C -> 8042F16C -> [call 8042F184] 8042E254
```

`[0x800A35D8,0x800A360C)` is a lazy accessor: reads `[r13+0x2DD8]`, initializes it via `0x800A360C` if null, returns it (D:160615-160627). Each manager wrapper loads manager `+0x40`, skips its operation if null, and passes that pointer as r3 to the core. The direct branch index finds only the above wrapper-to-core call sites; indirect or interior-entry possibilities are not disproved by that index (`ppc_tools.py:12-25` scans direct opcode-18 branches only).

State allocation at `0x8042F224` is **0x13C bytes**, saved at manager `+0x40`. Core state fields recovered from loads/stores:

```text
+00  u8 enabled                 +01 u8 alpha (zero also disables both passes)
+04  f32 scale                  +08/+0C two copied/interpolated words
+10  owner/manager pointer      +14 four draw vertices, stride 0x18
+74  history raster/view        +78 u8 history-valid gate
+7C  four half-size vertices    +DC four full-size vertices
```

Each vertex is `f32 x,y,z; u8 r,g,b,a; f32 u,v` (0x18 bytes). The parameter copiers transfer only bytes +0/+1, float +4, and words +8/+C; they do not copy padding +2/+3. The two parameter words at `+8/+C` are copied and the generic parameter effect interpolates them as floats, but **neither DrawBlur nor SaveScreen consumes them**. Do not silently interpret them as an effective blur center/velocity in the core implementation.

The bootstrap call sites are `0x801D1A80 -> 0x8042F20C` (null initial parameters) and `0x801D1AF0 -> 0x801D2058`; see D:470159-470191. Release is called at `0x801D19B8` per `branches.tsv:62534`; release destroys a distinct raster parent first, destroys the history view, frees state via `0x803A1334`, then clears manager `+0x40` (D:1090135-1090163).

## 3. DrawBlur core: exact control flow and arithmetic

### 3.1 Gates and camera acquisition

`0x8042E268-0x8042E2C8`, in this order:

1. Return if state enabled byte `+0` is zero.
2. Return if alpha byte `+1` is zero.
3. Call `0x8042B620` (returns `[0x805E25C8]`, D:1086329-1086332).
4. Call `0x803A1AFC` with r4=0, r5=`0x8056BCE4`, r6=`0x8056BCD0`, r7=0; return if null. This is an RTTI-cast-shaped dependency; type-descriptor contents remain to be checked.
5. Call cast-result vtable `+0x24`; return if the returned camera is null.
6. Return if state `+0x78` is zero.

There is **no loop, repeated sample kernel, velocity computation, or fctiwz in this core**. All early exits share the epilogue at `0x8042E824`.

### 3.2 Signed/unsigned geometry conversion

From camera `+0x60`, the pass obtains a raster/view. `0x8048AB7C` reads its signed halfword offsets `+0x1C/+0x1E`. View width/height are words at `+0x0C/+0x10`; root raster is `*view`, with root width/height at the same offsets. D:1089244-1089325; helper D:1183952-1183956.

Use the following symbolic constants until their original data words are freshly read:

| Constant | Original VA | Inferred use, not yet fresh-data-verified |
|---|---|---|
| H | 8051C388 | half-pixel/half-extent constant, expected 0.5f |
| O | 8051C38C | neutral scale, expected 1.0f |
| S-bias | 8051C390, 8 bytes | expected double 0x4330000080000000 |
| U-bias | 8051C398, 8 bytes | expected double 0x4330000000000000 |
| Z | 8051C3A0 | geometry zero, expected 0.0f |

`S(n)` below denotes the **actual signed-int conversion sequence**: xoris low word with 0x8000, combine with high word 0x43300000, lfd, fsubs S-bias. `U(n)` omits xoris and subtracts U-bias. The `fsubs`, unlike an ordinary double subtraction, rounds to single precision.

Writing `addS`, `subS`, `mulS`, `divS` for the respective single-precision PowerPC operations, the observed sequence is:

```text
x = sign_extend_16(view.offsetX); y = sign_extend_16(view.offsetY)
w = view.width word; h = view.height word
pw = root.width word; ph = root.height word

u0 = divS(addS(H, S(x)), U(pw))
u1 = divS(addS(H, S(add32(x,w))), U(pw))
v0 = divS(addS(H, S(y)), U(ph))
v1 = divS(addS(H, S(add32(y,h))), U(ph))

q  = subS(state.scale, O)
dy = mulS(H, mulS(q, S(h)))
dx = mulS(H, mulS(q, S(w)))
x0 = -dx; x1 = addS(S(w), dx)
y0 = -dy; y1 = addS(S(h), dy)
```

Thus source offsets and geometry widths/heights take the **signed** path, while root texture dimensions used as denominators take the **unsigned** path. Additions preceding xoris are 32-bit integer additions. No clamp or zero-dimension guard appears. Preserve operation ordering and f32 rounding: algebraically rewriting `(scale-1)*width/2` can change bits, and this code contains separate `fmuls` rather than fused arithmetic.

Vertex order at state `+0x14/+0x2C/+0x44/+0x5C` is `(x0,y0,u0,v0)`, `(x0,y1,u0,v1)`, `(x1,y0,u1,v0)`, `(x1,y1,u1,v1)`. RGB is set to 255 at each vertex and alpha is loaded with `lbz state+1`, stored with `stb`. Z values are retained from construction. The exact geometry-writing block is `0x8042E4F4-0x8042E600`, D:1089326-1089393.

### 3.3 Render states, draw, and restoration

Before geometry generation it retrieves state IDs `10,11,12,6,8,14,9` through `(*[0x805F265C])->function[0x24]`, passing an output pointer. After geometry it loads `root = *state.historyRaster` and calls camera begin `0x8048652C`; if begin returns null, it exits **without drawing**, although vertex data has already been updated.

On successful begin, the same engine table at `+0x20` receives:

| State ID | Value supplied | Standard RenderWare interpretation (numeric arguments are the primary evidence) |
|---|---|---|
| 1 | history raster root | texture raster |
| 10 | 5 | source blend = source alpha |
| 11 | 6 | destination blend = inverse source alpha |
| 12 | 1 | vertex alpha enabled |
| 6 | 0 | Z test disabled |
| 8 | 0 | Z write disabled |
| 14 | 0 | fog disabled |
| 9 | 1 | no culling |

At `0x8042E738`, indirect engine function `+0x30` is called with **r3=4, r4=state+0x14, r5=4**: the four-vertex triangle strip under the standard RW enum. It restores exactly the seven previously retrieved states and calls camera end `0x80486504` at `0x8042E820`. **Texture state 1 is not saved/restored here.** There is no clear of the history-valid byte in DrawBlur. D:1089195-1089243,1089394-1089534.

## 4. SaveScreen core and its half-size history allocation

### 4.1 Two-copy, two-draw control flow

The SaveScreen core first stores **0 to valid `+0x78` unconditionally** (`0x8042E850`), then checks enabled and alpha. It obtains the camera through the same getter/cast/vtable chain as DrawBlur, with the same null gates.

After successful acquisition:

```text
scratch = *(*(state.owner + 0x34))       // owner+34 -> texture-like object -> raster
copyEFB(scratch, 0)                      // 8042E8C0 -> 80496208
if (cameraBegin(camera)) {              // 8042E8C8 -> 8048652C
    setState(1, scratch)
    setState(10, 2); setState(11, 1)     // ONE / ZERO, standard RW enums
    draw(4, state+0x7C, 4)              // half-size quad, call 8042E954
    cameraEnd(camera)
}
copyEFB(state.historyRaster, 0)          // 8042E968 -> 80496208
if (cameraBegin(camera)) {              // 8042E970 -> 8048652C
    draw(4, state+0xDC, 4)              // full-size quad, call 8042E99C
    cameraEnd(camera)
}
state.valid = 1                         // 8042E9AC
```

Interpretation supported by the geometry and copy helper: capture the scratch image, render it down to the upper-left half-width/half-height region, capture that into history, then redraw the scratch image at full size. This is not a single `GXCopyTex(..., mipmap=true)` downsample: **both direct copy calls pass zero as the helper's scale/mipmap argument**; the half-size rendering performs the reduction.

Important fidelity details:

- The first begin failure does **not** prevent the history copy or second begin attempt.
- The second begin failure does **not** prevent `valid=1`.
- The copy helper returns no checked success value at either site.
- The second draw does not bind a new texture or reestablish blend state in this function; its intended scratch restoration relies on state left by the first successful block and the helpers.
- SaveScreen does not save/restore the seven states saved by DrawBlur.
- Whether this saved image is from an earlier frame at the eventual DrawBlur execution requires scheduler order/trace evidence. The two function bodies alone do not prove a frame interval.

### 4.2 Construction and copies

`[0x8042EA50,0x8042F084)` initially sets enabled=0, alpha=0, scale=O, owner=r4, saves optional parameter pointer r5. Only after camera acquisition succeeds does it initialize history pointer/valid to zero. The pass vertices' Z comes from engine table `+0x18`, and all vertex colors initially become 255. D:1089669-1089755.

It obtains full dimensions W/H from `*camera.raster`. It constructs a full-size strip at state `+0xDC` with positions `(Z,Z),(Z,S(H)),(S(W),Z),(S(W),S(H))` and UV endpoints `H/U(W), addS(H,S(W))/U(W)` and similarly for height. It copies that strip into `+0x7C`, preserving UVs/Z/colors, then changes positions to half dimensions. The integer halving is precisely:

```text
8042EE44  7C840E70  srawi r4,r4,1
8042EE48  7C840194  addze r4,r4
8042EE4C  7C630E70  srawi r3,r3,1
8042EE54  7C630194  addze r3,r3
```

This is **signed division by 2 with truncation toward zero**, not unsigned right shift and not floor division for negative odd inputs. D:1089920-1089927.

Calls at `0x8042F00C` and `0x8042F024` are respectively raster creation `(0,0,0,0x505)` and `(halfW,halfH,0,0x505)`. The first is retained as state `+0x74`; the second is supplied as parent to `0x8048AE14` at `0x8042F034`, with a rectangle whose width/height are halfW/halfH. Its initial X/Y words are copied from constants `0x8051C358/0x8051C35C`; verify these original words before asserting that they are zero. Keep raw raster flags **0x505** distinct from an unverified platform GX texture format.

If optional parameters are nonnull, the constructor invokes the checked parameter copier. Otherwise it explicitly sets enabled=0, **alpha=128**, scale=O at `0x8042F050-0x8042F068`. Constructor early exits occur before some later fields are initialized; do not invent a blanket memset or extra allocation failure handling absent from the observed instructions.

## 5. Actual motion-blur parameter arithmetic

### 5.1 Dynamic alpha writer and its direct caller

**`[0x800A47B0,0x800A4830)`**, D:161757-161788, builds the 16-byte parameter-shaped stack value and calls `0x8042F114` at `0x800A481C`. Only parameter +0/+1/+4 are explicitly initialized by this writer; its +8/+C stack words are not initialized before the copier transfers them. They must not be invented as intentional zero defaults (and the two core passes do not use them). The core calculations are:

```text
s = lfs(object + 0x38)
enabled = !(ordered_less(s, Czero) || ordered_equal(s, Czero))
scale = Cscale
alpha = low8(PPC_fctiwz(mulS(Calpha, s)))
```

The enabled predicate follows `FC010040` at `0x800A47D8`, `cror cr0eq,cr0lt,cr0eq` at `0x800A47DC`, then the conditional branch. Unlike a casual C `s > Czero` rewrite, unordered input reaches enabled=1. The alpha path `0x800A47FC-0x800A4810` is **fmuls -> fctiwz -> stfd -> lwz low result word -> stb**. Finite in-range conversion truncates toward zero into a signed integer; storing a byte takes low eight bits. There is **no saturation to 0..255** and no signed-byte interpretation. Exceptional fctiwz inputs must use PowerPC conversion semantics, not host-language undefined casts.

The r2 base is explicitly set to **0x805FA780** by `0x8000332C/0x80003330` (D:140-141), so this writer's actual constant locations are:

- `Czero`: r2-0x6BA4 = **0x805F3BDC**.
- `Calpha`: r2-0x6BA0 = **0x805F3BE0**.
- `Cscale`: r2-0x6BB0 = **0x805F3BD0**.
- Default scalar written before replacement: r2-0x6BB4 = **0x805F3BCC**.

Their raw contents remain a fresh-data follow-up; do not supply a guessed scale or guessed numeric alpha multiplier as recovered fact. Independent fixed writers do explicitly use integer alpha 128: enable path `[0x800A3714,0x800A37A4)` at `0x800A3730/0x800A374C`, and disable path `[0x800A3528,0x800A35D8)` at `0x800A353C/0x800A355C`. Those are separate entrypoints from the dynamic writer.

The direct dynamic writer caller is **`[0x800A4830,0x800A492C)`**, D:161789-161851, call at `0x800A48C4`. For its blur-relevant part, input f1 is divided using fdivs by `[0x805F3BD4]`; byte object `+0x34` selects subtraction or addition to object `+0x38`. The result is stored with stfs. Subtraction clamps only on ordered-less to Czero; addition clamps only on ordered-greater to `[0x805F3BCC]`. After the writer call, a final ordered-less-or-equal test to Czero sets task flag 1 at object `+4`. Other side effects in that enclosing function were not expanded into unrelated game analysis.

### 5.2 Generic parameter-effect blur case, not its other effect cases

The direct generic-effect function is `[0x80439A8C,0x8043A4B8)`, but **only its type-1 blur block `[0x80439EBC,0x80439FE0)`** is relevant here. D:1100948-1100980 establishes its dispatch; D:1101216-1101288 establishes this block and its setter call at `0x80439FD8 -> 0x8042F0E8`.

The function first invokes `0x8042B63C` to update progress, checks active bit 1 and exclusion bit 4 in `+0x18`, RTTI-casts its `+0x1C` owner, then dispatches on `*(object+0x108)`. Type 1 is the branch at `0x80439AFC` to `0x80439EBC`.

Let old parameters be object `+0x14C`, target parameters `+0x15C`, and t=`lfs object+0x100`. It starts with a target copy. If **ordered t < [0x8051CB58]**, it:

- ORs old/target enabled states into a Boolean.
- If the two alpha bytes differ, computes `fctiwz(fmadds(targetAlpha, t, fmuls(oldAlpha, fsubs([0x8051CB5C],t))))`, then stores the low byte.
- Applies the analogous separate old-product + **single-precision fused multiply-add** to floats at parameter offsets +4,+8,+C.

The alpha byte conversion uses `lbz`, **no xoris**, high word 0x43300000, and subtracts the double at **0x8051CB60**. It is an unsigned 0..255 conversion, not signed-char interpolation. The raw alpha sequence at `0x80439F68-0x80439F80` contains `EC010032`, `EC01013A`, `FC00001E`, `D8010080`, `80010084`, `98010015` (D:1101259-1101265). Preserving fused `fmadds` is essential; separate host mul+add can differ.

If the ordered-less predicate is false (including unordered comparison), it uses the unblended target copy. The constants at CB58 (threshold), CB5C (one-minus-t constant), and CB60 (unsigned conversion bias) need original-word confirmation; **do not assume the threshold equals 1 just because the interpolation constant is expected to be 1**.

Direct progress dependency `[0x8042B63C,0x8042B6CC)`, D:1086336-1086371: after flag checks, bit 2 permits `elapsed=addS(elapsed,dt)` at +0x0C. It compares against `addS([0x8051BFA4],duration)`; ordered-greater clears active bit 1. Otherwise it sets progress to `divS(elapsed,duration)` if duration is ordered-greater than `[0x8051BFA4]`, else `[0x8051BFA8]`, and clamps progress on ordered-greater to `[0x8051BFA8]`. This preserves the actual comparison/rounding structure without guessing those two constant words.

**Negative identification:** the reference-map label mentioning radial blur on the PJS global-parameter function is not enough to classify all its arithmetic as blur. In local `[0x801FA5EC,0x801FA83C)`, the extra type-4 block containing `fctiwz; clrlwi ...,0x18` at `0x801FA6F8/0x801FA704` ends in `0x80028984`, not the blur setter. Its base call at `0x801FA600` does reach the generic type-1 blur block above. Do not import the type-4 parameter layout/math into the blur reconstruction merely because of that map annotation.

## 7. Decoder and signedness pitfalls to preserve in reconstruction

- **Gekko paired-single instructions are not Power ISA VSX instructions.** In D:523063, raw `F3E10018` at `0x80205518` is printed as `xscmpeqdp vs31,f1,f0`; on this target it is **psq_st f31,0x18(r1),0,0**. Its matching `E3E10018` is psq_l, not data. This bounded example was encountered while inspecting a direct parameter-setter caller's surrounding boundary; it is not part of the blur core.
- At `0x801D2328/0x801D23A4`, `F3E10028/E3E10028` are similarly psq_st/psq_l save/restore (D:470715/470746). They are in a neighboring task, not evidence of a blur kernel. A decoder that stops at them can misassign subsequent task boundaries.
- **`FC010040` is fcmpo cr0,f1,f0**, even though the artifact prints `.byte` at the actual blur writer `0x800A47D8`, the generic blur case `0x80439EF0`, and several progress comparisons. Do not truncate a function there. `FC030040` and `FC020840` in the progress helper are corresponding ordered FP compares.
- `fctiwz` produces an integer-format FPR result; `stfd; lwz stack+4` extracts its low result word on big-endian PPC. `stb` or `clrlwi ...,24` subsequently reduces it modulo 256; it is not an unsigned floating-point conversion or saturating byte conversion.
- `clrlwi ...,16` after lha in the copy helper makes the GX argument **unsigned 16-bit**, despite signed halfword source storage. Conversely the draw's coordinate conversion uses those lha values as signed inputs.
- `srawi; addze` uses XER carry to implement signed truncating division; replacing it with an unsigned shift loses negative-input semantics.
- Ordinary `bge`/`ble` after fcmpo are tests of clear LT/GT bits. Translate the actual ordered comparison predicate, not an IEEE-C expression that changes the unordered case. The explicit `cror` sequences in the dynamic writer/update are significant.
- The two core pass bodies themselves contain **no paired-single instructions** in the inspected original listing. Their SIMD-looking gaps are not missing blur samples.
